商品画像を S3 / R2 から配る

EC-CUBE 本体を改造せずに、商品画像を Amazon S3 や Cloudflare R2 から配れます。ただし、本体が画像を書き込む先は手元のディスクのまま残します。その理由と手順です。

できること、やらないこと

大規模なサイトで画像に求められるのは、アプリのサーバーが画像を配らないこと、複数のサーバーで同じ画像が見えること、画像を失わないことの 3 つです。S3 はその手段の 1 つで、手間の少ない順に 3 通りあります。

構成画像を配るのは手間
NFS / EFS ＋ 前段の CDNCDN（初回だけアプリのサーバー）いまでもできる。設定だけ（大規模アクセス）
書き込みは手元、配信は S3 / R2S3 / R2 と CDN だけこのページの手順。設定ファイル 1 つと、写す仕組み
S3 / R2 だけに置くS3 / R2 と CDN だけやらない。本体の管理画面を 3 系列分書き換えることになる（下）
どれを選ぶか 画像の配信で困るのは、CDN を通さずにアプリのサーバーが画像を配っているときです。まず CDN を前に置き、それでもサーバーを並べる段になったら、NFS / EFS を用意するか、このページの構成にするかを選びます。このページの構成なら、管理画面を 1 台に決めておけば NFS / EFS は要りません（ほかのサーバーは画像を読まないため）。

S3 だけに置けない理由

EC-CUBE の管理画面は、画像を手元のディスクに直接書き、直接確かめます。4.2・4.3・4.4 のソースで、どれも同じ作りでした。

本体が手元のディスクを前提にしているところ

  • 商品画像の登録: アップロードされた画像をいったん html/upload/temp_image に置き、商品を保存したときに save_image へ移します（ProductController）。
  • 画像の削除: 消す画像が手元のディスクに実在するかを realpath() で確かめます（ProductType）。S3 にしか無いと、画像を消すたびに入力エラーになります。
  • 商品のコピー・CSV での一括登録・支払方法の画像も、手元のファイルを直接コピー・削除します。

表示する側は差し替えられる

  • 画像の URL は、テンプレートの asset(…, 'save_image') が決めています。中身は Symfony の設定 1 つで、本体を改造せずに CDN の URL へ向けられます。
  • 管理画面のプレビュー用の temp_image は、そのまま手元を指します。
  • S3 だけに置くには、上の処理を持つコントローラを写して書き換えることになります。写したものは、本体を上げたときに古いほうが勝ち続けるので、このキットではやりません。

書き込みは手元、配信は S3 / R2

管理画面が手元に書いた画像を、1 分おきにバケットへ写し、お客さんには CDN の URL で見せます。順番が大事です。先に写してから URL を切り替えます（逆にすると、写し終わるまで画像が出ません）。

1

置き場を作る

# Cloudflare R2 の例
バケット: shop-images
公開: カスタムドメイン
  img.example.com
# 書き込み用の鍵（このバケットだけ）

R2 なら、バケットにカスタムドメインを付けるだけで Cloudflare の CDN から配られ、配信の転送量もかかりません。S3 なら、バケットの前に CloudFront を置きます。鍵はこのバケットへの書き込みだけに絞ります。

2

鍵をリポジトリの外に置く

# /etc/eccube/rclone.env（chmod 600）
RCLONE_CONFIG_IMG_TYPE=s3
RCLONE_CONFIG_IMG_PROVIDER=Cloudflare
RCLONE_CONFIG_IMG_ACCESS_KEY_ID=…
RCLONE_CONFIG_IMG_SECRET_ACCESS_KEY=…
RCLONE_CONFIG_IMG_ENDPOINT=https://<アカウント ID>.r2.cloudflarestorage.com
RCLONE_CONFIG_IMG_REGION=auto
RCLONE_CONFIG_IMG_NO_CHECK_BUCKET=true

写すのは rclone で、設定は環境変数で渡します。店のリポジトリの中には置きません（.env.rclone のような名前は git に入ってしまいます）。NO_CHECK_BUCKET は、鍵をバケットだけに絞ったときに要ります（無いと、バケットを作ろうとして権限で止まります）。S3 なら PROVIDER=AWS、REGION=ap-northeast-1 にして、ENDPOINT の行を消します。

3

写すスクリプトを置く

# /usr/local/bin/eccube-img-sync（chmod 755）
#!/bin/sh
exec docker run --rm \
  --env-file /etc/eccube/rclone.env \
  -v <プロジェクト名>_eccube_upload:/upload:ro \
  rclone/rclone:1.76.0 \
  copy /upload/save_image \
  img:shop-images/save_image

商品画像は eccube_upload ボリュームの save_image にあります。<プロジェクト名> は docker volume ls | grep eccube_upload で確かめます。ボリュームは読み取り専用で渡すので、手元の画像には触りません。一度手で打って、いまの画像を全部写しておきます。

4

写し続ける

# crontab -e（管理画面を動かすサーバーで。1 行で書く）
* * * * * flock -n /tmp/img-sync.lock /usr/local/bin/eccube-img-sync

1 分おきに、まだ写していない画像だけを送ります（送り済みのものは比べるだけ）。flock は、前の回が終わる前に次の回が重ならないようにするためです。sync ではなく copy を使います（理由は下）。

5

URL を切り替える

# app/config/eccube/packages/image_cdn.yaml
framework:
  assets:
    packages:
      save_image:
        base_path: ~
        base_urls:
          - 'https://img.example.com/save_image'

base_path: ~ を省くと起動しません（本体が持っている値と両方になり、「An asset package cannot have base URLs and base paths」で止まります）。コミットして bin/deploy.sh で反映します。手順 3 で今の画像を写し終えてから。

6

確かめる

# 商品ページの画像の URL が CDN になっているか
curl -s https://店/products/detail/1 \
  | grep -o 'https://img[^"]*' | head -3
# その画像が返るか
curl -sI https://img.example.com/save_image/…

商品を 1 つ登録し直し、1〜2 分のうちに新しい画像も出ることを見ます。管理画面の画像のプレビューは手元を見るので、切り替えの前後で変わりません。

気をつけること

消した画像はバケットに残る

  • copy は送るだけで、バケットから消しません。管理画面で消した画像も、バケットには残ります。
  • sync にすると、手元にないものをバケットからも消します。手元のボリュームを作り直した・別のサーバーで動かした、といったときに、バケットの画像がまとめて消えます。残っている画像は URL を知らない限り誰も見ないので、置き場の料金が少し増えるだけです。

登録した直後は画像が出ないことがある

  • 写すのは 1 分おきなので、商品を保存してから次の回までは、お客さんの画面で画像が出ません。
  • その間に誰かが開くと、CDN が「無い」という返事をしばらく覚えることがあります（Cloudflare の既定では数分）。急ぐときは、その URL のキャッシュを CDN の画面で消します。

手元の画像が正、バックアップも今までどおり

  • バケットは配るための写しです。bin/backup.sh はこれまでどおり手元の画像を取ります。
  • asset() を通さずに画像のパスを直接書いているプラグインやテンプレートは、手元の URL のままです（4.4 の本体にも 1 か所あります）。手元にも画像は残っているので、出なくなることはありません。

サーバーを並べるとき

  • 管理画面を開くサーバーを 1 台に決め、cron もその 1 台だけで回します。ほかのサーバーは画像を読まないので、NFS / EFS は要りません。
  • 管理画面を複数のサーバーで開くなら、画像の置き場は NFS / EFS にして、cron はどれか 1 台で回します。

元に戻すとき

  • app/config/eccube/packages/image_cdn.yaml を消してコミットし、bin/deploy.sh。URL が手元に戻ります。
  • 手元の画像は一度も消していないので、戻してもそのまま出ます。cron は止めてから、バケットを片付けます。
正直に 確かめたのは 2 つです。URL を切り替える設定は、4.2・4.3・4.4 の配布イメージで、商品画像の URL が CDN になり、プレビュー用の temp_image とほかのファイルは手元のままになることを見ました。写す手順は、手元の実物の eccube_upload ボリュームから、S3 互換のテスト用サーバーへ写せることを見ました。本物の R2・S3・CloudFront と、本番で長く回したときの動きはまだ確かめていません。キットの機能としてはまだ入っていないので、試したら結果を Issue で教えてください。
