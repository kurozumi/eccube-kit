本番サーバーを用意する

サーバーを借りるところから、お店を公開して毎日のバックアップが回るところまで。AWS・Google Cloud・VPS のどれでも、守り方の決まりと後半の手順は同じです。このページで全体をつかんでから、借りる先のページへ進んでください。

できあがりの形

お客さんの通り道と、サーバーの外に置くものです。サーバーには外から入る口を 1 つも開けません（SSH を除く）。お客さんは Cloudflare を通って、サーバーが内側から張ったトンネルで届きます。

  1. 1Cloudflare入口
    • ドメインの管理（DNS）と HTTPS の証明書。お客さんのブラウザはここに繋がります。
    • Tunnel: サーバーのほうから Cloudflare へ繋ぎに行く道。サーバーの 80 / 443 番を開けずに公開できます。サーバーの IP アドレスが知られても、そこからお店には入れません。
    • 画像・CSS・JS をお客さんの近くから配る（CDN）。
  2. 2サーバー借りるところ
    • Docker の中でお店が動く（nginx・EC-CUBE・DB・Redis）。DB と Redis は外から届かない網の中にあります。
    • 外から入れるのは SSH（22 番）だけ。あなたのパソコンから、鍵を使って入ります。
  3. 3サーバーの外別の場所に置くもの
    • バックアップの置き場（S3・Cloud Storage・R2 など）。サーバーごと失っても、ここから戻せます。暗号化して送ります。
    • メールの送信サービス（SendGrid・Amazon SES など）。注文メールはここから送ります。サーバーから直接は送りません。
    • 必要になったら: 商品画像の置き場（S3 / R2 から配る）、マネージド DB。

どこで借りるか

迷ったら VPS から始めてください。お店が大きくなってからクラウドへ引っ越すこともできます（bin/backup.sh と bin/restore.sh で、データごと移せます）。

始める前に用意するもの

サーバーを借りる前に、次のものをそろえておきます。どれも無料か、すぐ用意できるものです。

ドメイン

Cloudflare に置いたドメイン

お店の住所（shop.example.com など）。ドメインを買ったところで、ネームサーバーを Cloudflare に変えておきます（Cloudflare の無料プランで足ります）。

コードの置き場

GitHub の非公開リポジトリ

お店のコードと設定の保存先。二段階認証を必ず有効に。ここを乗っ取られると、本番に何でも出せてしまいます。

作業する場所

あなたのパソコン

Mac か、Windows なら WSL2（Ubuntu）。サーバーへの作業はほとんど、パソコンから打つコマンドで済みます。パソコンでお店を動かすところまで先に済ませておきます。

秘密の控え

パスワードマネージャ

1Password・Bitwarden など。サーバーの .env、バックアップの暗号化の鍵、各サービスの復旧コードを控えます。ここに無いものは、失くしたら二度と戻りません。

メール

メールの送信サービス

SendGrid・Amazon SES・Resend など。注文メールの送り元のドメインを、そのサービスで確認（SPF / DKIM）しておくと、迷惑メールに入りにくくなります。

SSH の鍵

パソコンで作る鍵の組

サーバーに入るための鍵。パソコンで 1 回だけ作ります（下）。秘密鍵はパソコンから出しません。サーバーやクラウドに渡すのは公開鍵（.pub）だけです。

鍵

SSH の鍵を作る

パスワードの代わりに使う、サーバーに入るための鍵です。秘密鍵（id_ed25519）はパソコンにだけ置き、公開鍵（id_ed25519.pub）をサーバーに登録します。

もう持っているなら作らなくてよい。ls ~/.ssh/id_ed25519.pub でファイルが出れば、それを使います。

  1. パソコン鍵を作る

    ssh-keygen -t ed25519 -C shop

    保存場所を聞かれたら Enter（既定の ~/.ssh/id_ed25519）。パスフレーズは付けてください（パソコンを盗まれても、鍵だけでは入れません）。Mac なら一度打てばキーチェーンが覚えます。

  2. パソコン公開鍵を表示する

    cat ~/.ssh/id_ed25519.pub

    ssh-ed25519 AAAA… shop の 1 行が出ます。これがクラウドや VPS の画面に貼るものです。最後の shop は目印で、Google Cloud ではこれがログインするユーザー名になります。

守り方の決まり

どこで借りても、この 7 つを守ります。各ページの手順は、この決まりを画面の操作に落としたものです。

1. 入口を作らない

  • 公開は Cloudflare Tunnel で。サーバーの 80 / 443 番は開けません。
  • クラウドの「HTTP を許可」「HTTPS を許可」のチェックは外したままにします。
  • 開けていない口は、攻撃されようがありません。

2. SSH は鍵だけ、できれば自分の場所からだけ

  • パスワードでのログインと、root での直接ログインは止めます。
  • クラウドのファイアウォールで、22 番に入れる相手をあなたの IP アドレスに絞ります（自宅の IP が変わったら、その都度書き換えます）。

3. アカウントはすべて二段階認証

  • クラウド・VPS の管理画面、Cloudflare、GitHub、ドメインを買ったところ、メールの送信サービス。
  • サーバーより先に、管理画面のアカウントが狙われます。乗っ取られると、サーバーごと消されます。

4. サーバーに置く鍵は最小に

  • AWS・Google Cloud では、サーバーに「役割」（IAM ロール・サービスアカウント）を付け、鍵のファイルを置きません。
  • 置くしかないとき（VPS から R2 へ）は、1 つのバケットだけを扱える鍵にします。
  • バックアップの置き場は「足せるが消せない」権限にできるなら、そうします。サーバーが乗っ取られても、バックアップは消されません。

5. バックアップは暗号化して別の場所へ

  • DB のバックアップは、会員の氏名・住所・注文そのものです。bin/setup.sh backup が暗号化の鍵を作り、毎日 4 時に取って外へ送ります。
  • 暗号化の鍵はパスワードマネージャへ。鍵を失うと、すべてのバックアップが読めなくなります。

6. 更新を止めない

  • OS のセキュリティ更新は自動で入れ、ときどき再起動します。
  • PHP・nginx・DB の更新は bin/deploy.sh を打つたびに入ります（更新と反映）。

7. .env を控える

  • サーバーの .env には、DB のパスワードと ECCUBE_AUTH_MAGIC（全員のパスワードを確かめる鍵）が入っています。git には入りません。
  • 公開したら、中身をパスワードマネージャに写しておきます。これが無いと、引っ越し先で誰もログインできません。

キットが最初からしていること

  • 管理画面の URL を推測しにくい名前にする（admin-<乱数>）。
  • ログインとパスワード再発行の回数制限（1 つの IP から 1 分に 10 回）。
  • コンテナの権限を最小に絞る。DB と Redis はお客さんの通り道から届かない網に置く。
  • 本番の nginx はサーバーの中（127.0.0.1）にしか開かない。
ufw だけに頼らない Docker は、コンテナのポートを公開するとき、ufw（Ubuntu のファイアウォール）を通らずに穴を開けます。ufw で 443 番を閉じたつもりでも、caddy で公開していれば外から届きます。外から届く口は、クラウドや VPS の管理画面のファイアウォール（セキュリティグループ・パケットフィルター）で決めてください。Tunnel で公開していれば、そもそも開けるポートがありません。

サーバーができたら、どこでも同じ

各ページの手順で「SSH で入れるサーバー」ができたら、ここに戻ってきます。ここから先は、ぜんぶあなたのパソコンから打ちます。shop は、各ページで ~/.ssh/config に書いたサーバーの呼び名です。

A

お店を載せて公開する

1 つずつ、終わったのを見てから次へ進みます。どのコマンドも、間違った設定のまま書き込まないように、先に試してから書きます。

時間: 30 分ほど。

サーバーに git は置きません。お店のファイルはパソコンから送ります。サーバーに GitHub の鍵を置かずに済みます。

  1. サーバー時刻を日本時間にする

    ssh shop 'sudo timedatectl set-timezone Asia/Tokyo'

    クラウドのサーバーは最初、世界標準時（日本より 9 時間遅れ）です。このままだと「毎日 4 時のバックアップ」が日本の昼 1 時に走ります。

  2. サーバーDocker を入れて、お店のファイルを送る

    bin/bootstrap-server.sh shop /srv/myshop

    Docker が無ければ入れ、お店のファイルを送り、サーバーの .env（パスワード類）を作ります。起動はまだしません。

  3. サーバーメールの送り方を決める

    bin/setup.sh mail --remote=shop:/srv/myshop

    使うサービスを選んで質問に答えると、試しに 1 通送ります。届いたものだけを書きます。サーバーから直接は送りません（クラウドはメールの 25 番を塞いでいて、送れても迷惑メールに入ります）。

  4. ブラウザCloudflare で Tunnel を作る

    Cloudflare の画面で Zero Trust → Networks → Tunnels → トンネルを作成（種類は Cloudflared）。表示されたトークン（長い文字列）をコピーします。公開するホスト名（shop.example.com）の行き先は http://nginx:80。

  5. サーバーTunnel のトークンを入れる

    bin/setup.sh tunnel --remote=shop:/srv/myshop

    トークンを貼ると、繋がるかを試してから書きます。

  6. サーバー公開する

    bin/publish.sh --remote=shop:/srv/myshop

    パスワードがまだ既定値のまま、メールが未設定、といったときは止まります。止まったら、出ている指示どおりに直してからもう一度。

  7. サーバーバックアップを毎日取る

    bin/setup.sh backup --remote=shop:/srv/myshop

    送り先（各ページで作ったバケット）を選び、暗号化の鍵を作り、1 回取ってみて、毎日 4 時の自動実行に登録します。表示された暗号化の鍵を、パスワードマネージャへ。

  8. パソコン.env を控える

    ssh shop 'cat /srv/myshop/.env'

    出てきた全文をパスワードマネージャに貼ります。画面に出したあとは、ターミナルの履歴を消しておくと安心です。

B

Cloudflare の設定

ブラウザで、Cloudflare のお店のドメインを開いて設定します。既定のままだと困るものだけです。

  1. ブラウザいつも HTTPS で開くようにする

    SSL/TLS → エッジ証明書 →「常に HTTPS を使用」をオン。http で来たお客さんを https へ送ります。

  2. ブラウザキャッシュの持ち時間をお店に任せる

    キャッシュ → 構成 →「ブラウザキャッシュ TTL」を「既存のヘッダーを尊重」に。既定の 4 時間のままだと、管理画面で直した CSS がお客さんのブラウザに 4 時間残ります。

  3. ブラウザページ全体をキャッシュする設定は使わない

    「すべてをキャッシュ」（Cache Everything）のルールは作りません。カートやログインの入ったページを、ほかのお客さんに配ってしまいます。

  4. ブラウザボット対策は、決済で試してから

    「Bot Fight Mode」を入れると、決済会社からの通知（データセンターから届く）まで止められることがあります。入れるなら、テスト決済で注文が「入金済み」になるところまで確かめてください。

公開の前に確かめる

1 つでも「いいえ」があれば、そこを直してから告知します。

入口

  • https://お店のドメイン/ が開き、鍵のマークが出る。
  • サーバーの IP アドレスを直接ブラウザで開いても、お店が出ない（Tunnel なら何も返らない）。
  • パスワードでの SSH が断られる（各ページの確かめ方）。

お店

  • テスト注文をして、注文メールが届く（迷惑メールフォルダも見る）。
  • テスト決済で、注文が「入金済み」になる。
  • 管理画面の URL が admin-<乱数> になっている。

バックアップ

  • バケットに、今日の日付のフォルダがある。
  • 暗号化の鍵と .env の全文が、パスワードマネージャにある。
  • 次の朝、もう 1 日分増えている（cron が動いている）。

アカウント

  • クラウド・Cloudflare・GitHub・ドメイン・メールの送信サービスが、すべて二段階認証。
  • 料金の通知（予算）を設定した。
  • 外から死活を見る（UptimeRobot などで / を 5 分おき）。
正直に このページと各クラウドのページは、キットのコマンドと設定を実物に照らして書きました（SSH の設定ファイルが読まれる順番、rclone の設定、ポートの開き方など）。クラウドの管理画面の項目名と配置はよく変わります。書いてある名前が見つからないときは、そのボタンで「何をしたいか」（たとえば「22 番に入れる相手を自分の IP だけにする」）で探してください。それでも分からなければ、お問い合わせからどうぞ。
