VPS で始める

VPS を注文するところから、最初のログイン、SSH の守りを自分で固め、バックアップを Cloudflare R2 へ送るところまで。終わったら どこでも同じ後半 へ進みます。

先に知っておく言葉

サーバー

VPS

1 台の大きな機械を区切って貸してもらう、自分専用のサーバー。さくらの VPS・ConoHa VPS・Xserver VPS などがあり、料金は月額で決まっています。

ファイアウォール

パケットフィルター

VPS の管理画面で設定する「どの番号の口を開けるか」の決まり。会社によって「セキュリティグループ」「ファイアウォール」とも呼びます。サーバーの外で効くので、これがいちばん確かです。

管理者

root と sudo

root はサーバーで何でもできる特別なユーザー。ふだんは自分用のユーザーで入り、必要なときだけ sudo を付けて root の力を借ります。

ファイルの置き場

Cloudflare R2

Cloudflare のファイル置き場（S3 と同じ使い方ができる）。ドメインを Cloudflare に置いているので、同じ画面で使えます。バックアップと、必要なら商品画像の置き場に。

サーバーを固めるまで

VPS の会社ごとに画面は違いますが、決めることは同じです。会社の画面で見つからない項目は、その会社のマニュアルで同じ名前を探してください。

A

注文する

大きさの目安: 最低 2 コア・メモリ 4GB・ディスク 50GB 以上（PHP が 20 本で約 1.6GB、キャッシュの組み立てに 1GB、DB に 0.5GB を使います）。商品やアクセスが多いなら 8GB。

  1. ブラウザ管理画面のアカウントに二段階認証

    VPS の会社の会員ページで、二段階認証を有効にします。ここを乗っ取られると、サーバーを再インストールされて、すべて消えます。

  2. ブラウザOS と地域

    OS は Ubuntu 24.04（「アプリ」「テンプレート」ではなく素の OS）。地域を選べるなら東京か大阪。

  3. ブラウザroot のパスワードと SSH 鍵

    root のパスワードは、パスワードマネージャで作った長いものに（すぐに使わなくなりますが、念のため）。SSH 鍵を登録できるなら、作った公開鍵（~/.ssh/id_ed25519.pub の中身）を登録します。

  4. ブラウザパケットフィルター

    SSH（22 番）だけを許可し、Web（80 / 443）は許可しません（公開は Tunnel で、外から入る口は要りません）。許可する相手を IP アドレスで絞れるなら、自分の IP に（curl -s https://api.ipify.org で調べられます）。

B

最初のログインと、自分用のユーザー

最初は root で入ります。root のまま作業を続けず、自分用のユーザー（ここでは shop）を作って、以後はそちらで入ります。

入ったターミナルは閉じない。この節と次の節が終わって、新しいユーザーで入れることを別の窓で確かめるまで、最初の窓は開いたままにします。閉じ出されても、この窓から直せます。

  1. パソコンroot で入る

    ssh root@203.0.113.10

    IP は VPS の管理画面に出ています。鍵を登録していればそのまま、していなければ root のパスワードを聞かれます。会社によっては最初のユーザーが ubuntu のこともあります（そのときは ssh ubuntu@… で入り、以下の adduser からの手順に sudo を付けます）。

  2. サーバー更新して、自分用のユーザーを作る

    apt-get update && apt-get -y upgrade
adduser shop            # パスワードを 2 回聞かれる（コンソールで入るときに使う）
usermod -aG sudo shop

  3. サーバーsudo をパスワード無しにする

    echo 'shop ALL=(ALL) NOPASSWD:ALL' > /tmp/90-shop
visudo -cf /tmp/90-shop && install -m 440 /tmp/90-shop /etc/sudoers.d/90-shop

    キットはパソコンから SSH 越しに sudo を打つので、パスワードを聞かれると止まります。AWS や Google Cloud のサーバーも最初からこの設定です。shop はこのあと Docker を動かすグループに入り、どのみち root と同じことができるので、sudo のパスワードは守りになりません。守りは「鍵を持っている人しか入れない」ことのほうです（次の節）。visudo -cf は書き間違いの検査で、parsed OK と出たときだけ入れます。

  4. サーバー鍵を新しいユーザーへ写す（root に鍵を登録した場合）

    install -d -m 700 -o shop -g shop /home/shop/.ssh
install -m 600 -o shop -g shop /root/.ssh/authorized_keys /home/shop/.ssh/authorized_keys

    root にパスワードで入った場合は、代わりにパソコンから ssh-copy-id shop@203.0.113.10（shop のパスワードを聞かれます）。

  5. パソコン呼び名を書いて、新しいユーザーで入ってみる

    # ~/.ssh/config に足す（ファイルが無ければ作る）
Host shop
  HostName 203.0.113.10
  User shop
  IdentityFile ~/.ssh/id_ed25519
    # 新しいターミナルの窓で
ssh shop
sudo whoami    # パスワードを聞かれずに root と出れば OK
C

SSH を固める

パスワードでのログインと、root での直接ログインを止めます。鍵を持っている人しか入れなくなります。

ファイル名は 00- で始める。SSH は設定ファイルを名前の順に読み、最初に読んだ値を使います。VPS の多くは 50-cloud-init.conf に「パスワードを許可」と書いてあり、99- のような名前にすると負けて、パスワードのログインが残ります（Ubuntu 24.04 で確かめました）。

  1. サーバー設定を書く

    sudo tee /etc/ssh/sshd_config.d/00-eccube.conf >/dev/null <<'EOF'
PasswordAuthentication no
KbdInteractiveAuthentication no
PermitRootLogin no
EOF

  2. サーバー書き間違いがないかを見て、効かせる

    sudo sshd -t && sudo systemctl restart ssh

    sshd -t が何も言わなければ書き間違いはありません。何か出たら、直すまで restart しません。

  3. サーバー効いているかを見る

    sudo sshd -T | grep -E "^(passwordauthentication|kbdinteractiveauthentication|permitrootlogin) "

    3 つとも no なら大丈夫です。

  4. パソコン別の窓で、入れること・パスワードでは入れないことを確かめる

    ssh shop 'echo ok'
ssh -o PubkeyAuthentication=no -o PreferredAuthentications=password shop@203.0.113.10

    1 行目が ok、2 行目が Permission denied (publickey) なら成功です。ここまで確かめたら、最初の root の窓を閉じて構いません。

D

ファイアウォールと自動更新

サーバーの中でも SSH 以外を閉じ、OS のセキュリティ更新が毎日入るようにします。

ufw は Docker を止められない。Docker はコンテナのポートを開くとき ufw を通りません。Tunnel で公開するなら開くポートは無いので困りませんが、外から届く口の決め手は、管理画面のパケットフィルターのほうです。

  1. サーバーufw で SSH だけ開ける

    sudo ufw allow OpenSSH
sudo ufw enable        # 「SSH が切れるかも」と聞かれたら y
sudo ufw status

    OpenSSH ALLOW の行があれば大丈夫です。allow OpenSSH を先に打ってから enable。逆にすると、その場で締め出されます（VPS の管理画面の「コンソール」から入って直せます）。

  2. サーバーOS の自動更新を確かめる

    systemctl is-enabled unattended-upgrades

    enabled なら、セキュリティ更新は毎日自動で入ります。出なければ sudo apt-get install -y unattended-upgrades && sudo dpkg-reconfigure -plow unattended-upgrades（「はい」）。

  3. サーバー月に 1 回、再起動する

    ls /var/run/reboot-required 2>/dev/null && sudo reboot

    カーネルの更新は、再起動するまで効きません。ファイルがあれば「再起動が要る」という意味です。お客さんの少ない時間に。お店は自動で立ち上がります。

E

バックアップの置き場（Cloudflare R2）

VPS には AWS や Google Cloud のような「サーバーの役割」が無いので、鍵をサーバーに置くことになります。そのぶん、鍵は 1 つのバケットだけに絞ります。

古いバックアップは R2 が消す。バケットの決まり（ライフサイクル）で、30 日たったら消えるようにします。VPS の会社の「自動バックアップ」（ディスクごとの控え）も、あれば併せて使うと安心です。

  1. ブラウザバケットを作る

    Cloudflare の画面 →「R2 オブジェクト ストレージ」（初回は利用の申し込み。無料枠があります）→「バケットを作成」→ 名前 myshop-backup、場所は「アジア太平洋」。公開アクセスは有効にしません。

  2. ブラウザ30 日で消える決まりを作る

    バケット →「設定」→「オブジェクト ライフサイクル ルール」→ ルールを追加 → 30 日後にオブジェクトを削除。

  3. ブラウザこのバケットだけの鍵を作る

    R2 の画面 →「API トークンを管理」→「API トークンを作成」。権限「オブジェクト読み取りと書き込み」、「特定のバケットのみに適用」→ myshop-backup。作ると「アクセスキー ID」「シークレット アクセスキー」「エンドポイント（https://<アカウント ID>.r2.cloudflarestorage.com）」が出ます。シークレットはこのとき 1 回しか表示されません。パスワードマネージャへ。

  4. サーバーrclone を入れて、送り先を登録する

    sudo apt-get install -y unzip && curl -fsSL https://rclone.org/install.sh | sudo bash
rclone config create r2backup s3 provider=Cloudflare \
  access_key_id=<アクセスキー ID> secret_access_key=<シークレット> \
  endpoint=https://<アカウント ID>.r2.cloudflarestorage.com \
  region=auto no_check_bucket=true
chmod 600 ~/.config/rclone/rclone.conf

    no_check_bucket=true は、バケットを作ろうとしない設定です（このバケットだけの鍵には、その権限がありません）。鍵は ~/.config/rclone/rclone.conf に入るので、自分しか読めないようにします。

  5. パソコンあとは共通の手順で

    どこでも同じ後半の「バックアップを毎日取る」で bin/setup.sh backup を打ったら、「1) rclone」→ 送り先 r2backup → パス myshop-backup/myshop と答えます。

知っておくこと

メールはサーバーから直接送らない

  • 多くの VPS は、迷惑メール対策でメールの 25 番を塞いでいます。送れても、VPS の IP からのメールは迷惑メールに入りがちです。
  • SendGrid・Resend・Amazon SES などの送信サービスを使い、bin/setup.sh mail --remote=shop:/srv/myshop で入れます（587 番）。

商品画像を R2 から配る

  • バックアップとは別のバケットと、そのバケットだけの鍵を作ります。手順は 商品画像を S3 / R2 から配る。
  • R2 はバケットにカスタムドメイン（img.example.com）を付けるだけで Cloudflare の CDN から配られ、配信の転送量もかかりません。

入れなくなったら

  • VPS の管理画面にある「コンソール」（ブラウザから直接サーバーの画面を開く機能）から入れます。SSH の設定やファイアウォールを間違えても、ここから直せます。
  • そのために、shop のパスワードはパスワードマネージャに控えておきます。

止まったら知らせる

  • UptimeRobot などで https://お店のドメイン/ を 5 分おきに見ます。
  • VPS の会社の障害情報のページも、ブックマークしておきます。

やらないこと

  • root のままで作業を続ける。打ち間違い 1 つで取り返しがつきません。
  • パスワードでの SSH を残す。世界中から総当たりで試されます。
  • R2 の鍵を「すべてのバケット」に効くもので作る。漏れたときの被害が、そのアカウントの全部になります。
  • 「アプリ」「テンプレート」の EC-CUBE を選ぶ。VPS の会社が用意した EC-CUBE は、このキットとは別物です。素の Ubuntu を選びます。
次へ 新しいユーザーで SSH に入れて、バックアップの置き場ができたら、どこでも同じ後半へ進みます（時刻を日本時間に → Docker とファイル → メール → Tunnel → 公開 → バックアップ）。
